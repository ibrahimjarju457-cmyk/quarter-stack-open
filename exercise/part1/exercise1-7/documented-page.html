HTML Structure Study Guide

Written for classmates in Intro to Web Development, ahead of the first quiz. It covers how an HTML page is organised, why heading levels matter, and the three kinds of list.

The document skeleton

Every page starts with a doctype declaration, followed by an html element holding exactly two children: a head and a body.

What goes in the head

The head holds information about the page rather than content shown on it. The items below are the ones the validator expects.

  • meta charset, so text displays correctly
  • title, shown in the browser tab
  • meta viewport, so phones scale the page properly

What goes in the body

The body holds everything visible. Landmarks such as header, nav, main and footer tell screen readers where they are.

Heading hierarchy

Use one h1 per page, then nest h2 through h6 without skipping levels. Choose headings for their meaning, never for their size; size is the job of CSS.

Common mistakes

  1. Jumping from h2 straight to h4
  2. Using several h1 elements for visual emphasis
  3. Using bold paragraphs where a heading belongs

Lists

HTML has three list types. Pick the one that matches the content.

ul (unordered)
Items where order does not matter.
ol (ordered)
Steps or rankings where order matters.
dl (description)
Terms paired with their definitions, like this one.

Pre-quiz checklist

Before the quiz, make sure you can do each of these from memory:

  • Write a valid page skeleton without looking
  • Explain why heading levels must not be skipped
  • Choose the correct list type for a given example
